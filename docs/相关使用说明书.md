> 本文档面向前端开发工程师和Agent开发工程师

## 一、快速启动

### 1.1 环境准备

```bash
# 1. 进入项目目录
cd smart-research-assistant

# 2. 创建虚拟环境（推荐）
conda create -n rag_agent python=3.10
conda activate rag_agent

# 3. 安装依赖
pip install -r requirements.txt

# 4. 配置API密钥
#    复制 .env.example 并重命名为 .env
#    然后编辑 .env，填入你自己的API Key
cp .env.example .env
```

### 1.2 获取API Key

本项目默认使用 DeepSeek API（也可以用硅基流动或其他OpenAI兼容平台）：

1. 访问 https://platform.deepseek.com 注册账号（注册送¥5）
2. 在控制台创建 API Key
3. 编辑 `.env` 文件，将 `SILICONFLOW_API_KEY=` 后面填入你的Key

```env
SILICONFLOW_API_KEY=sk-你的key
SILICONFLOW_BASE_URL=https://api.deepseek.com
CHAT_MODEL=deepseek-v4-pro
```

### 1.3 启动服务

```bash
python main.py
```

启动成功后会显示：

```
╔══════════════════════════════════════════════════╗
║        智能科研助理 RAG API 服务                  ║
║   地址: http://0.0.0.0:8000                      ║
║   文档: http://0.0.0.0:8000/docs                 ║
╚══════════════════════════════════════════════════╝
```

首次启动会自动下载Embedding模型（约1.2GB）和Reranker模型（约80MB），请耐心等待。


### 1.4 验证服务是否正常

浏览器打开 http://localhost:8000/docs ，可以看到 Swagger 交互式API文档，直接在页面上测试所有接口。

## 二、API接口清单

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| **RAG问答** | POST | `/api/query` | ⭐ 核心接口，支持流式SSE |
| 纯检索 | POST | `/api/search` | 只检索不生成（Agent用） |
| 纯生成 | POST | `/api/generate` | 只生成不检索（Agent用） |
| 上传文档 | POST | `/api/documents/upload` | 上传论文并建索引 |
| 文档列表 | GET | `/api/documents` | 查看已上传的文档 |
| 删除文档 | DELETE | `/api/documents/{filename}` | 删除指定文档 |
| 健康检查 | GET | `/health` | 服务状态检查 |
| 系统统计 | GET | `/api/stats` | 运行统计数据 |

**Base URL：`http://localhost:8000`**

## 三、前端的对接指南

### 3.1 上传文档

```javascript
// FormData上传
const formData = new FormData();
formData.append('file', fileInput.files[0]);

const response = await fetch('http://localhost:8000/api/documents/upload', {
  method: 'POST',
  body: formData
});

const result = await response.json();
// result: { status: "success", filename: "xxx.pdf", pages: 8, chunks: 33 }
```

### 3.2 对话问答（流式输出）

这是最核心的接口。用 `stream: true` 实现打字机效果：

```javascript
const response = await fetch('http://localhost:8000/api/query', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    question: '这篇论文的主要方法是什么？',
    session_id: 'session_001',
    top_k: 5,
    stream: true
  })
});

// 使用 ReadableStream 读取 SSE 事件
const reader = response.body.getReader();
const decoder = new TextDecoder();

while (true) {
  const { done, value } = await reader.read();
  if (done) break;

  const text = decoder.decode(value);
  // text 格式为多条 "data: {...}\n\n"
  const lines = text.split('\n\n');

  for (const line of lines) {
    if (line.startsWith('data: ')) {
      const event = JSON.parse(line.slice(6));

      switch (event.type) {
        case 'thinking':
          // 显示系统状态："正在检索相关文献..."
          showStatus(event.content);
          break;

        case 'reference':
          // 显示引用来源卡片
          // event.ref_index: 引用序号
          // event.doc: 文档名
          // event.page: 页码
          // event.content: 段落摘要（前100字）
          addReferenceCard(event);
          break;

        case 'chunk':
          // 逐字追加到回答区域（打字机效果）
          appendToAnswer(event.content);
          break;

        case 'done':
          // 生成完成
          // event.content: 完整回答文本
          // event.reference_count: 引用数量
          // event.elapsed_time: 总耗时（秒）
          showComplete(event);
          break;

        case 'error':
          // 错误信息
          showError(event.content);
          break;
      }
    }
  }
}
```

### 3.3 对话问答（非流式）

如果不需要打字机效果，可以用非流式直接拿完整JSON：

```javascript
const response = await fetch('http://localhost:8000/api/query', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    question: '这篇论文的主要方法是什么？',
    stream: false
  })
});

const result = await response.json();
// result.answer: 完整回答文本（含 [来源: xxx, 第X页] 引用标记）
// result.references: 引用来源数组
// result.elapsed_time: 响应耗时
```

### 3.4 SSE事件类型速查

| type | 何时触发 | 关键字段 |
|------|----------|----------|
| `thinking` | 系统处理中 | `content`: 状态描述 |
| `reference` | 发送引用来源 | `ref_index`, `doc`, `page`, `content` |
| `chunk` | 逐字输出 | `content`: 文本片段 |
| `done` | 生成完成 | `content`: 完整回答, `elapsed_time` |
| `error` | 出错 | `content`: 错误信息 |

## 四、Agent的对接指南

### 4.1 RAG作为Agent的工具

Agent可以通过三种方式调用后端能力：

#### 方式一：完整RAG（检索+生成）

```
POST /api/query
{
  "question": "PPO算法的训练参数是什么？",
  "stream": false,
  "top_k": 5
}
```

返回完整的回答和引用来源。适合Agent判断用户问题需要查论文时直接调用。

#### 方式二：纯检索（只搜不生成）

```
POST /api/search
{
  "query": "PPO算法 训练参数",
  "top_k": 5
}
```

返回格式：
```json
{
  "results": [
    {
      "content": "段落文本内容...",
      "source": "uploads/paper.pdf",
      "page": 3,
      "chunk_id": "paper.pdf_p3_c12",
      "rrf_score": 0.086,
      "retrieval_method": "hybrid_rrf_rerank"
    }
  ],
  "count": 5
}
```

适合Agent自己组织上下文后调用 `/api/generate` 生成回答，或者Agent自己处理检索结果。

#### 方式三：纯生成（给定上下文生成回答）

```
POST /api/generate
{
  "question": "总结以下内容的核心观点",
  "context": [
    {
      "content": "段落1内容...",
      "source": "paper1.pdf",
      "page": 3
    },
    {
      "content": "段落2内容...",
      "source": "paper2.pdf",
      "page": 1
    }
  ]
}
```

返回格式：
```json
{ "answer": "生成的回答文本..." }
```

适合Agent用自己的工具链收集到上下文后，调用大模型生成最终回答。

### 4.2 推荐的Agent工具注册

建议将以下三个接口注册为Agent的工具：

| 工具名 | 对应接口 | 使用场景 |
|--------|----------|----------|
| `knowledge_search` | `POST /api/search` | 在论文库中搜索相关内容 |
| `knowledge_qa` | `POST /api/query` | 直接向知识库提问获取完整回答 |
| `text_generate` | `POST /api/generate` | 给定上下文生成回答/总结 |

### 4.3 Agent调用示例（伪代码）

```python
# 用户问："对比论文A和论文B的方法差异"

# Step 1: Agent决定先检索两篇论文的相关信息
results_a = call_api("/api/search", {
    "query": "论文A 核心方法",
    "top_k": 3
})

results_b = call_api("/api/search", {
    "query": "论文B 核心方法",
    "top_k": 3
})

# Step 2: Agent合并上下文
combined_context = results_a["results"] + results_b["results"]

# Step 3: Agent调用生成接口进行对比分析
answer = call_api("/api/generate", {
    "question": "对比这两篇论文的核心方法差异",
    "context": combined_context
})

# Step 4: 返回给用户
return answer["answer"]
```

## 五、常见问题

### Q1: 启动报错怎么办？

```bash
# 先跑一下测试，确认基础功能正常
python main.py --test
```

如果测试通过但启动失败，检查 `.env` 文件中的 API Key 是否正确。

### Q2: 上传文档后提问没有回答？

检查日志（控制台输出），看是否有报错信息。常见问题：
- API Key 无效 → 检查 `.env`
- 模型下载失败 → 设置 `HF_ENDPOINT` 镜像

### Q3: 回答质量不好？

- 多上传几篇相关论文
- 调大 `top_k`（最多20）获取更多参考
- 确保上传的是文字版PDF（不是扫描件）

### Q4: 接口响应很慢？

- 首次提问会比较慢（需要加载模型），后续会快很多
- 命中语义缓存时几乎秒回
- 如果持续很慢，检查网络连接

### Q5: 前端跨域问题？

后端已经配置了 CORS 允许所有来源（`allow_origins=["*"]`），正常不会有跨域问题。如果有，检查前端请求的 URL 是否正确。

```

│
├── uploads/               # 上传的文档（运行时生成）
```
