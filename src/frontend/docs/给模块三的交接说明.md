## 三、模块三开发红线与注意事项（按重要性排序）

1. **不要修改模块一/二现有接口的契约**：`/api/query`、`/api/search`、`/api/generate`、`/api/documents*`、`/health`、`/api/stats` 的字段名与行为，我和模块五（QA）都已按现状开发完毕。你要扩展就**加可选字段或新端点**，保持向后兼容。
2. **端点与代码归属**：交付 `POST /api/agent/query`（请求体 = 现有 `QueryRequest`：question/session_id/top_k/stream）。代码建议放新目录 `src/agent/`，然后在 `src/api/app.py` 里挂一个新 router——Git 提交按目录分界，答辩时各模块归属清晰。不要直接改 `src/frontend/` 下的任何文件；改后端 `routes.py` 前先和模块一/二负责人沟通。
3. **SSE 硬要求：每轮恰好以一个 `done` 或 `error` 收尾**。前端靠它判定回合结束；缺失会等到 120s 超时报"流中断"。这是协议里唯一的"违约即挂"条款。
4. **工具事件字段名按协议 3.2**：`thought.content`；`action.{content, tool, args}`；`observation.{content, tool}`。前端对 tool/args 有别名兼容（tool_name/arguments/params），但请输出标准键。
5. **别用 HTTP 自己回环调自己**：`knowledge_qa` 对应 `/api/query`——若 Agent 就部署在同一 FastAPI 进程里，再走 HTTP 回环既绕又可能超时叠加。建议直接注入复用 `routes.py` 里那个全局 `_rag_pipeline` 实例（或参照 `app.py:_initialize_services()` 的装配方式拿对象），`search()` / `generate()` 都是现成方法。
6. **语义缓存的坑（重要调试提示）**：模块二的缓存判定=问题语义相似度≥0.95，且**删除文档不清缓存、不清向量**（已知 bug，模块一/二负责人修复中）。你调试时若发现"改了 System Prompt / 换了策略，答案纹丝不动"——先怀疑缓存命中（后端日志有 `缓存命中 (相似度=…)`）。临时解法：重启后端（缓存只在内存）；长期解法：Agent 通道内自行控制是否走缓存，或在你的端点里先 clear。
7. **异常兜底**：ReAct 内部任何异常（LLM 超时、工具炸了、死循环强杀）请转成 `error` 事件正常收尾，**不要抛裸 HTTP 500**——前端对 500 只会显示"后端返回 HTTP 5xx"，用户看不到原因；error 事件则能展示你的错误摘要。
8. **404 自动降级**：你的端点没部署期间，前端请求会得到 404 → 自动回退 RAG 直连并显示"Agent 通道尚未就绪"。所以**不必为等我而提前赶工**，什么时候交付什么时候切 `USE_AGENT=true`。
9. **推理模型兼容**：DeepSeek 推理型模型 `content` 为空需回退 `reasoning_content`，模块二已处理（`rag_pipeline.py:124` 附近）；你若自行调 LLM SDK，同样的逻辑要抄一份。
10. **统计口径**：前端监控面板目前只读 `/api/stats` 的固定字段。你要暴露 Agent 专属指标（工具调用成功率、平均推理轮次、按工具 Token 分布，对应作业 5.4.2），**不要改 StatsResponse**，新增一个 `GET /api/agent/stats`，和我打个招呼，前端接一个面板十几分钟的事。
